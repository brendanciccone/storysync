---
description: Audit Figma file against code and report drift in either direction
argument-hint: "[figma-file-key]"
---

Compare the current Figma file against this codebase's design tokens and Storybook components, then report drift in either direction. Use the storysync skill at `.claude/skills/storysync/SKILL.md` (Audit section).

**Figma file key:** $ARGUMENTS

If the user did not provide a file key (or `$ARGUMENTS` is empty), ask for it. The file key is the part of a Figma URL between `/design/` and the next `/`.

Workflow:

1. Read Figma variables — call `use_figma` to enumerate every variable collection and its resolved values (use `figma.variables.getLocalVariableCollectionsAsync()` and convert COLOR values to hex, `#rrggbb` with the alpha as two more digits when it comes to less than `ff`). `use_figma` returns at most 20kb per call, which a full palette passes, so read them a slice per call with the skill's template, from the `next` each call returns until it is `null`.
2. Read Figma components — call `use_figma` to enumerate every component set and its variant properties, and every component outside a set (the push makes a component with no variant properties a plain component), a page at a time: `use_figma` loads pages as it switches to them and does not support `figma.loadAllPagesAsync()`, so a search from `figma.root` sees only the pages already loaded and misses the sets on the rest. List the pages (`figma.root.children`), then make one call per page with the skill's template: it switches to the page with `figma.setCurrentPageAsync`, uses `page.findAllWithCriteria({ types: ['COMPONENT_SET', 'COMPONENT'] })` without the sets' variants, and returns each one's `nodeId`, type, the `storybookId` the push stored on it (`getSharedPluginData('storysync', 'id')`) and `componentPropertyDefinitions`, as many per call as fit under 20kb, from the `next` each call returns as in step 1. Figma throws `Component set has existing errors` reading a set it flags as errored: the template returns that set with its `error` and reads on.
3. Run `npx storysync tokens --json --project .` for code-side tokens.
4. Run `npx storysync map --storybook http://localhost:6006 --json` for code-side components. Pass the `--exclude-props` the push used, if any, from the `excludeProps` at the top of `.storysync/snaps/styles.json`, or ask the user if that has none and they say the push left props out; otherwise every prop it left out is reported missing from Figma. If the user asked about some components only, pass them with `--components` rather than map every component, which can take many minutes, and also run `npx storysync list --storybook http://localhost:6006 --json` for every component's `id`, `title` and `category`, to pair with in step 6.
5. Compare tokens by name within each category. Normalize before comparing: compare a color by its token's `hex` and a length by its `px` (rem and `calc()` worked out) where the token has one; otherwise lowercase hex, convert rem→px, strip units. A translucent color is `#rrggbbaa` on both sides: compare all eight digits. Round numbers to thousandths on both sides. Match Figma collection names to code categories (Colors→colors, Border Radius→radius, etc.).
6. Compare components by Storybook ID first: a Figma component whose `storybookId` is a code component's `id` is that component's, whatever its name or page (two with it, as a copy of a set has, are told apart by page as below), and one whose `storybookId` no code component has is Figma only, never paired with another component by name. Compare the code components no ID paired with the sets that have no `storybookId` by set name (case-insensitive): the last segment of a component's `title`, or its `name` without one, or its `name` where no set has that and it is no other component's set name. A name only one code component and one set have is a pair. If two code components share a name, or two Figma component sets do (on different pages: an archived copy, say, or each category's own `Button`), counting those an ID paired, pair a component with the set of its name on its category's page (`Components` without one, comparing page names ignoring case, spaces, `/`, `-` and `_`) where each is the only one of the name on that page on its side; of the copies left, code's alone are code only and Figma's alone Figma only. Copies left on both sides, even one of each, can't be told apart (a set on another page may be the component's, moved, or an archived copy beside a component not pushed yet): report the name as ambiguous, and only as ambiguous: compare none of the copies left, and don't also count them as matched, mismatched or missing. A component outside any set with no `storybookId` may be a designer's own, such as an icon: it pairs only with a code component the sets left code only, of its set name and on its category's page, each the only one there, and never makes a name ambiguous. One left unpaired is not one the push made, since the push stores a `storybookId` on each component it makes: don't list it as Figma only, but count it as not compared, unless the scope names it. A set with an `error` pairs as any set, but is reported as errored in Figma (can't read its properties), by name, page and `nodeId`, with nothing in it compared; don't delete it unless the user asks. When the audit is scoped, pair with every component `list` gave, but compare and report only those in scope, and a Figma component paired with none only if the scope names it. For each pair: missing props, extra props, missing/extra values per prop.
7. Report drift grouped by category/component:
   - `+` missing from Figma (in code, not in Figma)
   - `-` missing from code (in Figma, not in code)
   - `~` value mismatch (both exist, values differ)
   - `?` ambiguous (a name two code components or two Figma component sets share, none of its copies compared)
   - `!` errored in Figma (a set whose properties Figma won't give, compared with nothing)
8. End with a summary: N tokens matched / mismatched / missing. N components matched / mismatched / code-only / Figma-only / ambiguous / errored in Figma, and N components outside any set not from the push, not compared. Confirm "Figma and code are in sync." only if everything matches and no name is ambiguous or set errored; components outside any set not from the push don't count against it. An ambiguous name was compared on none of its copies, and an errored set on nothing, so either can hide drift: while any is, name them instead, and never say the two are in sync.

Refer to `.claude/skills/storysync/SKILL.md` Audit section for the full procedure and edge cases.
