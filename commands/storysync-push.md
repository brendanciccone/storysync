---
description: Sync Storybook components and design tokens from code to Figma
argument-hint: "[figma-file-key]"
---

Push design tokens and Storybook components from this codebase into Figma using the storysync skill at `.claude/skills/storysync/SKILL.md`.

**Figma file key:** $ARGUMENTS

If the user did not provide a file key (or `$ARGUMENTS` is empty), ask for it. The file key is the part of a Figma URL between `/design/` and the next `/`.

Workflow:

1. Run `npx storysync tokens --json --project .` to extract design tokens from the project. If no tokens are found, skip token sync and continue with components.
2. For each token category, call `use_figma` to create or update a matching Figma variable collection. Use `COLOR` for colors and `FLOAT` for numeric tokens, setting each `FLOAT` variable from its token's `px`, which has rem (16px) and `calc()` worked out (`calc(0.625rem - 4px)` is 6). A weight or a unitless line height has no `px` and is its own `value`; leave out, and name, any other `FLOAT` token with no `px` (one in em or %) and any token a `tokens` warning starting `Unresolved:` names. A token whose `value` keeps a `var()` but has a `px` or `hex` did resolve; set it from those. If no token has a `px` at all, an older storysync ran: use a plain rem `value` times 16, or a px one as is, in place of `px`. Set each color from its token's `hex` (`figma.util.rgba(token.hex ?? token.value)`), not its `value`, which can be `oklch()` or bare HSL channels that `figma.util.rgb` rejects.
3. Run `npx storysync map --storybook http://localhost:6006 --json` to get component variant mappings. If Storybook isn't running on port 6006, ask the user for the correct URL.
4. **REQUIRED — Measure the styling, don't infer it.** Run `npx storysync snap --storybook http://localhost:6006 --variants all --json` now, in this session. It renders every combination in a real browser and reports the computed styles: fill, text color, border, radius, padding, font, shadow, and auto-layout. Output is a base variant plus per-variant deltas; a variant's full styles are the base with its `delta` applied. Do not reuse an earlier `styles.json` — it may describe code that has since changed. Build one Figma variant per snap variant, whatever its status — a component set needs every combination. If a component has a `cap` field (more combinations than the limit, 256 by default), stop and ask the user before building it: build the measured subset (its `uncovered` list names any values it leaves out), re-run with `--max-combinations <total>`, or narrow which props are variants: re-run snap with `--exclude-props` naming the props that don't change how it looks, such as `modal` or `loop`, which leaves them out of every component. Do not offer to infer the rest from source — they can be measured. For a `timeout`, which snap already tried twice if the story was loading, re-run snap for those components with `--components` and a longer `--timeout` first. Only for variants whose `status` is still not `"ok"`, fall back to reading source, and resolve tokens via `npx storysync tokens --json` rather than a memorized class-to-value table. Where snap warns that it measured a closed trigger or a layout wrapper rather than the component, or that a prop's values all measured the same, build what was measured, labeled `measured`, rather than styling it from source. Figma's plugin context loads only Google Fonts, so never let a font fail the push: load each text layer's font with the skill's `loadFont`, which falls back to a stand-in at the measured weight, Roboto Mono for a monospace face such as Menlo and Inter for any other, a CSS keyword such as `system-ui` included, and returns each stand-in in the part's `fonts`. `verify` won't score a keyword family as drift; a platform face such as Menlo it scores, so report its stand-in as a substitution, not drift to fix.
5. Group components by their `category` field. Create one Figma page per category, the whole of it (`Forms`, `Data Display`, `ui/base`), and a `Components` page for those without one, finding an existing page ignoring case, spaces, `/`, `-` and `_` as the skill's step 5 template does. Place each component set on its category's page, named by the last segment of its `title` (`Button` for `ui/base/Button`), or by its `name` when it has no title, so `ui/base/Button` and `ui/radix/Button` stay two sets.
6. Call `use_figma` per component, embedding the measured values from step 4. `use_figma` takes at most 50,000 characters of code per call, so build a set of more than 25 variants in parts of 25, in snap's variant order, as the skill's step 5 describes, leaving out of each entry `border` where `borderUniform` is set and `borderRadius` where `borderRadiusUniform` is, which only repeat them; if a part's code passes 45,000 characters, build that set in parts of 15 instead. Update an existing component set of the same name rather than creating a duplicate, finding it anywhere on its page (`page.findAllWithCriteria({ types: ['COMPONENT_SET'] })`, since a designer may have moved it into a section or frame) and asking the user which to update if more than one has the name: each part updates the variants it names, finding each in the set by name, adds only the ones the set lacks, never creates a second variant of a name the set already has, and refuses, before changing anything, a set that already holds two of a name it carries, so a part can be retried and a push repeated. Every part lays the whole set out again and checks it, so a part re-run on its own leaves the set laid out. A variant in Figma that snap no longer has is named by no part and left alone, in a row of its own below the others; step 7 finds it. Report it, and delete one only if the user asks. A component with no variant properties is one plain component, its one variant named `''`, not a set: Figma renames a set's one unnamed variant `=` and marks the set as broken. The template refuses to build beside a set of that name a push before 0.4.0 left, or a set where a plain component of its name is, before changing anything: ask the user whether to convert it, as the skill's step 5 says, or to skip the component. A new set or component goes 100 below everything on its page, never at `0,0` on top of another, and one already there stays where it is; each carries the component's Storybook `id` and `title` as shared plugin data (`node.getSharedPluginData('storysync', 'id')`), so the first part also finds an earlier set by that id. Bind fills/spacing/radius/typography/shadows to the variable collections from step 2 where possible, setting every fill, stroke and effect with the template's `setPaints`, never by assigning it: Figma resets a paint assigned freshly bound to a variable to opacity 1, so a translucent color loses its alpha, and `setPaints` puts it back. A part whose own styling code throws removes the variants it created before it fails. Use `strokeAlign = 'OUTSIDE'` on hugging frames (a CSS border always adds to an auto-sized element's outer size, whatever `boxSizing` says), and give a transparent border, a `borderUniform` whose `color` is `null`, a stroke of its weight with a paint that draws nothing (`opacity: 0`) rather than no stroke, since it takes its space in the browser all the same. The browser paints the fill under a transparent or translucent border unless `backgroundClip` is `padding-box`: with `padding-box` keep the `OUTSIDE` stroke, where Figma's fill stops too, and without it build that border `INSIDE`, with `strokesIncludedInLayout = true` on a hugging frame, so the fill runs under it and the stroke still adds to the size. Build a measured `width` or `height` of 0 as 0.01, the least Figma takes. A color snap writes `#rrggbbaa` is translucent: give it as `#rrggbb` with the paint's `opacity` at `aa` / 255 (`#4b556322` is `#4b5563` at about 0.133), or for a shadow as the effect color's `a`. Lay the set out with the skill's step 5 template, giving every part the component's `variantProperties` from snap's output, copied as they are: it orders the set by them, never by the set's children, whose order is whatever an earlier push or a designer left. Each property's values run in the order snap records them: a `VARIANT`'s default value first, then the rest in the order of the component's prop type as Storybook's docs list it (a story's `argTypes` options are not read), and a `BOOLEAN` property runs its default first, `false, true`, or `true, false` when it defaults to `true`, whatever order snap lists its values in; the first property's values are the rows, and the combinations of the other properties, the last varying fastest, the columns, so the Button in snap's example is three rows, primary, danger and outline, of four columns: sm, sm disabled, lg, lg disabled. With one property, each value is a row of one. Figma makes the top-left variant the set's default variant, so the default is the variant of each property's first value: the component's own default for a `VARIANT`, since snap records it first, and for a `BOOLEAN`, since its default runs first: `open=true` where the component defaults to `open=true`. When that differs from the component's defaults, as where a snap from before 0.4.0 lists a `VARIANT`'s values as Storybook's docs do, say in the summary which variant Figma will treat as the default. A property marked `defaultAssumed: true` has no default in Storybook's docs, so its `defaultValue` is a guess: name those in the summary too. The template takes each variant's cell from its name, so the work grows with the set's variants, not with every combination. A variant snap does not have goes in a row of its own below the others and is counted as `extra`, as is a second variant of a name: the one whose node id sorts first as text stays in the grid, so every part keeps the same one there. The template refuses a set whose `layoutMode` is not `'NONE'` before changing anything, since auto layout positions the variants itself and would flow the last one into the top-left: ask the user whether to turn auto layout off on the set and re-run the part, or to leave its layout alone and skip the set, saying in the summary that it was not pushed. Figma's layers panel shows the last child at the top, so the variants go last to first, moving only those out of place, and the panel reads in the grid's order. The template grows the set to fit, then asserts the layers are in that order, that every variant is where the layout put it, so a move Figma ignored fails, that no two variants' bounding boxes intersect and that the set contains them all (geometry comparison only catches variants clipped by an undersized frame, not same-sized ones stacked inside a big enough one), and ends the plugin code by returning the set's id, name and variant count, counts of the rows, columns and extra variants, and the font stand-ins as `fonts`. Not the readback: `use_figma` returns at most 20kb per call, which a whole set's readback passes at a few dozen variants.
7. Read each set's variants back with the skill's step 6 template, in separate calls of at most 20 variants, in snap's variant order: each call carries only its own variants' names, slugs and sources, finds the set by the id the build returned, and reads the actual properties off the nodes — don't echo what you sent; colors come back as snap writes them, since verify compares colors as written: `#rrggbb`, then the alpha, the paint's `opacity`, as two more hex digits when they come to less than `ff`, and `null` for a paint that draws nothing, hidden with `visible: false` or of an alpha that comes to `00`; width/height are the node's own size plus the stroke outside it by `strokeAlign`, painted or not, never `absoluteRenderBounds`, which leaves out a stroke that paints nothing and takes in drop shadows, unlike snap's border box. A plain component reads in one call, its one variant named `''` with the slug `default`, and a `total` of 1. Write the entries each call returns into `.storysync/figma-readback.json` exactly as returned, merging the slices, keyed by component title (its `id` when it has none) and snap variant slug, with the set's id as `nodeId`, each component its own set's, each variant carrying `"source": "measured"` or `"inferred"`: copy each entry whole, its `readAt` and `checksum` included, numbers digit for digit, a `null` as `null` (the template returns every field on every variant, the text's fields and `gap` as `null` where there is no text child or auto layout), and never fill in or recompute a value, from snap, from what you sent in step 6 or from anywhere else, nor reuse an entry from an earlier run. If a response is too long to copy whole, read fewer variants per call rather than summarizing it. Each entry's `checksum` is computed by the template in Figma over that entry, its `readAt`, the set's id and the slug, and `verify` flags any entry whose checksum is missing or doesn't match, whose component has the `nodeId` of another, that lacks a field the template always returns, or that was read before the snap, as an unverified readback, scores nothing in it, and fails `--strict`. If the slices add up to fewer variants than the `total` each call returns, or a build part returned an `extra` other than 0, the set holds variants snap never measured. Find them by listing the set's names a slice at a time with the skill's template (`componentSet.children.slice(START, START + 100).map((c) => c.name)` a call, since every name in one call can pass 20kb) and comparing them with snap's yourself, and report them. If a readback call throws, deal with what it names and make it again: for `The set has 0 variants named …`, add it to the set by id (re-run the build part that names it, which adds only what the set lacks and lays the whole set out again), then read that slice again; for `The set has 2 variants named …`, a repeated or retried part made it twice, so report it, and remove the stale copy only after checking which one is current, or ask the user; if step 6 raised it, the refused part changed nothing, and the parts after it never ran: re-run that build part and every part after it, through the last part, then read the slices; for a slice too close to 20kb, split its names across two calls and lower the batch for the slices after them. Then run `npx storysync verify --strict-age`. Fix what it flags by node ID, read the set back again, and re-run, stopping after two rounds. An `unscored` variant means the readback returned nothing comparable — re-read it; an unverified readback means that entry is not what the call returned, not all of it, or not from this run — read that slice again, now, with the template as it is, and write its entries as returned, each component under its own set's id, never editing the file to make it pass; a recorded snap failure means re-run `snap`; a `width` a pixel or two off on a variant that hugs its text, with nothing else on it drifting, is usually Figma setting the text about a pixel apart from the browser, so report it as a font-rendering difference rather than squeezing the text's width, which can clip the label, but only when the variant's stroke is `OUTSIDE`, `INSIDE` with `strokesIncludedInLayout`, or it has none, and the difference is not exactly twice the measured border's weight. Otherwise check its `strokeAlign` first: an `INSIDE` stroke on a hugging frame without `strokesIncludedInLayout` leaves the variant short by exactly twice the border, a `CENTER` one by the border, and a transparent border built with no stroke by twice the border too, and each is a build mistake to fix, not font rendering. A `fontFamily` the parts' `fonts` name a stand-in for is not fixable in Figma either: report it.
8. Summarize what was synced: token collections (count per category), components grouped by page, variant counts, the components built as one plain component for having no variant properties, the fidelity score, measured versus inferred counts, any story that didn't pass its args through, any component snap warned it measured as a closed trigger or a layout wrapper (with the fix the warning gives), every font stand-in the build parts returned in `fonts` (a CSS keyword such as `system-ui` set in Inter, a platform face such as Menlo in Roboto Mono), any component where `fontAvailable` was `false` (the measurement describes a substituted typeface, and Figma will need that font installed — storysync cannot install it), which variant Figma will treat as a set's default where that is not the component's default, any set skipped for its auto layout, any component skipped for a set or plain component of its name an earlier push left, any variant built 0.01 wide or high for a measured 0, the variants with a transparent border, and any failures or caps. For each variant with a transparent or translucent border, say how its fill meets that border, as the browser draws it: with `backgroundClip: padding-box` the fill stops at the border, and Figma's `OUTSIDE` stroke leaves the same unfilled ring; without it the fill runs under the border, built as an `INSIDE` stroke with `strokesIncludedInLayout`. A transparent border built any other way, such as an `OUTSIDE` stroke where the background is not clipped, shows an unfilled ring the browser fills: say so, and that a stroke tinted the background's color would hide it, which `verify` will then score as a border color the code does not have.
